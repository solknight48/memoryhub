# MemoryHub development

`mh` — git-like checkpoints for purified AI session context. Python ≥3.12, uv-managed, Typer CLI over system git.

- Run tests: `uv run pytest` (E2E: subprocess against `python -m memoryhub` in a hermetic HOME — never the real one)
- Local install: `uv tool install -e .`. On PyPI the distribution is `memoryhub-mh` (`memoryhub` is another project's) while the import package and command stay `memoryhub` / `mh` — hence the explicit `packages = ["src/memoryhub"]` in pyproject, guarded by `tests/test_packaging.py`. A release is a `vX.Y.Z` tag on a commit whose `__version__` and CHANGELOG say X.Y.Z: `release.yml` checks that, runs the suite, builds and publishes through PyPI trusted publishing (GitHub environment `pypi`, no token)
- Layout: `src/memoryhub/{cli,hub,git,purify,checkpoint,load,agents,curate,save,live,memory,templates,compact,server,hooks}.py`; skill and UI ship as package data in `src/memoryhub/{skill,ui}/`
- `curate.py` is the ONLY code that parses session markdown (load/show/search read files verbatim). It must never rewrite a file whose parse→re-render is not byte-identical — that guard is what keeps editing safe for dialog quoting mh's own headings. Mutations call `ensure_committable()` before touching disk, so a failed commit can't leave a change outside the journal
- `live.py` owns the session that is still running: the newest transcript of the project, purified in memory for the UI's live panel, plus the *draft* of curation done while it runs (`<hub>/drafts/<key>.json`, kept out of the journal via `.git/info/exclude`). The draft is applied by every save path — `_resolve_session()` folds it in, so `mh save`, `mh save --compact` and the hooks all agree — which is what stops a later save from resurrecting dialog the user curated away mid-session. Entries are keyed by transcript exchange number and carry the original user text as an anchor: when the in-flight turn changes under an entry (consecutive unanswered messages merge into one turn) the entry is ignored, never applied to different dialog
- The live panel reads `agents.stream()`, not `extract()`: everything the agent emitted (thinking, text, tool calls) grouped per exchange. It is display-only — saves always store the purified dialog. The grouping reuses the turn builders' own text functions (`purify.user_text`, `_pi_user_text`, …) rather than restating the boundary rules, and `from_discovered()` drops the stream entirely if its length ever disagrees with the turns. Tool calls emitted in one reply are marked as a parallel batch (`batch`/`batch_size`) — Claude Code writes one record per content block, so the record boundary says nothing and `message.id` is the only thing that does. Verified formats only (claude, pi); codex returns None and the page falls back to dialog, same policy as the model labels
- `memory.py` reads Claude Code's per-project auto-memory (`~/.claude/projects/<project>/memory/`: `MEMORY.md` index + one frontmatter+markdown file per note) for the map's read-only "Project memory" section. mh never writes this folder — it is Claude Code's, shown beside the checkpoints. The frontmatter parser handles top-level scalars plus the one-level `metadata` map; `[[name]]` links become related-chips, and a note's `originSessionId` resolves through `live.find` to an "open session" jump, same plumbing as trace
- Provenance is by session id, never a stored path: the purified file's header records the transcript id (`curate.parse().session_id`), and `live.find(hub, sid)` resolves it against the project's current transcripts on demand — `mh trace` and the session panel's "open original" both use it, and both degrade honestly when the transcript is gone or came from another machine. "Open original" opens `?view=<sid>`: the same page in viewer mode (body.viewonly — only the live panel, `LIVE_PINNED` null so it never lets go, all exchanges), never a switch of the map's own live panel — the user wants the purified session and its source on separate pages
- A **stage** is a column of the timeline and may hold several checkpoints (`ck.stages()`): by name, a trailing `-N` is another take at the same stage (`design-2` → `design`); `ck.create(..., stage=)` / `--at` records an exception in `<hub>/stages.toml`, which `curate._relink` keeps honest on rename/delete. Stages change nothing about load, links or `current` — only where the map draws a node and what the template counts as reached
- `skip.toml` in the hub lists the sessions (`ckpt/file`) that `mh load` leaves out — `mh skip`/`mh unskip`, or the checkbox on the map's session row. `load.build` is the one place that filters by it (so the CLI, the SessionStart hook and the map agree), and `curate._reskip` keeps the ids following renames and moves and leaving with deletes, in the same commit as the change
- A **sub-checkpoint** is a checkpoint stored inside its parent's directory (`checkpoints/<stamp>_design/<stamp>_head-page/`) and named by the dotted path (`design.head-page`; `Checkpoint.leaf` is its own name, `.parent` the slug above). `list_checkpoints` flattens the tree in creation order, so indices, `back`/`forward` and `resolve` see one list. It sits at its parent's stage (`stage_of` reads the root), never forms a column and never reaches a template stage. `load.build` adds the ancestors of every selected checkpoint before the link closure — a scope includes what it sits in. `curate._names`/`_follow` treat `old`, `old.x` and `old/file` alike, so a parent's rename or delete carries the subtree's links, placements, skips and the current pointer
- `templates.py` holds the stage templates (default checkpoint names per kind of project). Choosing one writes `<hub>/template.toml` with a *copy* of the stages (tracked, editable — the project owns its sequence); nothing is created up front. `progress()` is the one reading of "where the project stands": the next stage is the first whose slug has no checkpoint, and `mh checkpoint` with no name, `mh status`, and the map's dashed nodes all derive from it. The map edits the list through `set_stages()` (validated: non-empty, distinct slugs; one commit), and `curate.rename_checkpoint` calls `rename_stage()` so a renamed stage-checkpoint does not leave its stage "still ahead"
- `compact.py` is the only place mh calls a model, and it never owns one: it runs the session's CLI in print mode (`claude -p --no-session-persistence --max-turns 1 --tools ""`, `pi -p --no-session --no-tools --no-extensions …`) in a scratch cwd with the nested-session env scrubbed (`CLAUDECODE`, `CLAUDE_CODE_*`, `TMUX*`), feeds it the purified dialog plus that tool's own compaction prompt (pi's verbatim), and stores the answer through `save.store(replace_compacted=True)`. Never `--bare` for claude — it skips the login state. The running session is never touched; nothing is typed into a pane
- `save.py` is the ONE place a session document lands in the hub: `mh save`, `mh hook save` and the live panel all call `save.store()`. A session lives in exactly one checkpoint — no target follows it to where it already is, an explicit other target moves it, and only an explicit `mh save` may replace a compacted summary with dialog. Do not write sessions with `ck.write_session` + `git.auto_commit` from anywhere else (`mh import` is the one exception: a batch landing in one commit)
- `purify.TurnBuilder` is the one turn-pairing rule (unanswered questions merge; an unanswered slash command is dropped; models credited per exchange). The claude/pi/codex adapters in `agents.py` only walk their own record shapes and feed it
- Lint and format are `ruff` (config in pyproject; CI runs `ruff check` and `ruff format --check`); the suite runs under xdist by default (`addopts = -n auto`), so every test must stay hermetic
- `server.py` is stdlib-only on purpose: typer stays the single runtime dependency. `dispatch()` is a plain function so the API is tested without a socket. Every map and live response carries `hub_rev` (`_hub_rev`: the reflog's mtime plus the current pointer); the page compares it on each live poll and re-reads the map when it moves, which is how a terminal-side `mh link`/`mh goto`/hook save reaches the page without a refresh
- `purify.py` is vendored from `~/.claude/skills/purify-context/purify.py` — keep extraction semantics identical (the parity test in `tests/test_purify.py` pins this). One intended divergence: a slash command (`<command-name>` wrapper) is dialog when the agent answered it — kept as the user typed it, `/mh load` — and dropped when nobody did (a local command such as `/clear` or `/model`); the original drops them all. The parity fixture's only command is unanswered, so the byte-for-byte assertion still holds
- Presentation deliberately diverges: `render()` emits `## User N` / `## Agent N` where the original emits `## QN` / `## AN`. The parity test stays byte-for-byte by relabelling the original's output via `as_mh_format()`; extend that helper, don't weaken the assertion, if rendering changes again
- Per-turn models ride *beside* the turns (`models: list[str]`, parallel to `turns`), never inside the tuple — so a transcript naming no model renders exactly what the original does, and the parity fixture stays model-free to keep pinning the real save path. Anything that reorders or drops turns (`drop_trailing_unanswered`, `delete_exchange`) must move the model with them
- To actually look at the UI: `mh ui --no-browser --port 7777`, then `chromium --headless=new --no-sandbox --hide-scrollbars --window-size=900,9000 --virtual-time-budget=12000 --screenshot=/tmp/shot.png "$URL"` and read the PNG (slice tall pages into bands with pillow). CSS and JS are served from disk per request, so a reload is enough; only `server.py` changes need a restart
- The UI's pure JS (markdown renderer, model labels) is tested for real: `tests/uijs.mjs` slices the functions out of the shipped `index.html` and runs them against a DOM shim; call them from Python with `run_ui_js(...)` in `conftest.py`. These tests skip without `node`, which both CI runners have
