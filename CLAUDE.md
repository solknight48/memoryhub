# MemoryHub development

`mh` — git-like checkpoints for purified AI session context. Python ≥3.12, uv-managed, Typer CLI over system git.

- Run tests: `uv run pytest` (E2E: subprocess against `python -m memoryhub` in a hermetic HOME — never the real one)
- Local install: `uv tool install -e .`
- Layout: `src/memoryhub/{cli,hub,git,purify,checkpoint,load,agents,curate,save,live,relay,server,hooks}.py`; skill and UI ship as package data in `src/memoryhub/{skill,ui}/`
- `curate.py` is the ONLY code that parses session markdown (load/show/search read files verbatim). It must never rewrite a file whose parse→re-render is not byte-identical — that guard is what keeps editing safe for dialog quoting mh's own headings. Mutations call `ensure_committable()` before touching disk, so a failed commit can't leave a change outside the journal
- `live.py` owns the session that is still running: the newest transcript of the project, purified in memory for the UI's live panel, plus the *draft* of curation done while it runs (`<hub>/drafts/<key>.json`, kept out of the journal via `.git/info/exclude`). The draft is applied by every save path — `_resolve_session()` folds it in, so `mh save`, `mh save --compact` and the hooks all agree — which is what stops a later save from resurrecting dialog the user curated away mid-session. Entries are keyed by transcript exchange number and carry the original user text as an anchor: when the in-flight turn changes under an entry (consecutive unanswered messages merge into one turn) the entry is ignored, never applied to different dialog
- The live panel reads `agents.stream()`, not `extract()`: everything the agent emitted (thinking, text, tool calls) grouped per exchange. It is display-only — saves always store the purified dialog. The grouping reuses the turn builders' own text functions (`purify.user_text`, `_pi_user_text`, …) rather than restating the boundary rules, and `from_discovered()` drops the stream entirely if its length ever disagrees with the turns. Tool calls emitted in one reply are marked as a parallel batch (`batch`/`batch_size`) — Claude Code writes one record per content block, so the record boundary says nothing and `message.id` is the only thing that does. Verified formats only (claude, pi); codex returns None and the page falls back to dialog, same policy as the model labels
- `relay.py` types into a live session from the browser: it pastes into the tmux pane the session runs in (bracketed paste + Enter, so a multi-line message stays one message). The pane is recorded by `mh hook load` from `TMUX_PANE` (`<hub>/panes.json`, untracked) and re-verified on every send — the pane must still exist and the recorded agent pid must still be alive inside it, else mh refuses rather than pasting into whatever took the pane. Fallback for unrecorded sessions: match this project's agent processes to panes by /proc ancestry, and only act when exactly one matches
- `save.py` is the ONE place a session document lands in the hub: `mh save`, `mh hook save` and the live panel all call `save.store()`. A session lives in exactly one checkpoint — no target follows it to where it already is, an explicit other target moves it, and only an explicit `mh save` may replace a compacted summary with dialog. Do not write sessions with `ck.write_session` + `git.auto_commit` from anywhere else (`mh import` is the one exception: a batch landing in one commit)
- `purify.TurnBuilder` is the one turn-pairing rule (unanswered questions merge; an unanswered slash command is dropped; models credited per exchange). The claude/pi/codex adapters in `agents.py` only walk their own record shapes and feed it
- Lint and format are `ruff` (config in pyproject; CI runs `ruff check` and `ruff format --check`); the suite runs under xdist by default (`addopts = -n auto`), so every test must stay hermetic
- `server.py` is stdlib-only on purpose: typer stays the single runtime dependency. `dispatch()` is a plain function so the API is tested without a socket
- `purify.py` is vendored from `~/.claude/skills/purify-context/purify.py` — keep extraction semantics identical (the parity test in `tests/test_purify.py` pins this). One intended divergence: a slash command (`<command-name>` wrapper) is dialog when the agent answered it — kept as the user typed it, `/mh load` — and dropped when nobody did (a local command such as `/clear` or `/model`); the original drops them all. The parity fixture's only command is unanswered, so the byte-for-byte assertion still holds
- Presentation deliberately diverges: `render()` emits `## User N` / `## Agent N` where the original emits `## QN` / `## AN`. The parity test stays byte-for-byte by relabelling the original's output via `as_mh_format()`; extend that helper, don't weaken the assertion, if rendering changes again
- Per-turn models ride *beside* the turns (`models: list[str]`, parallel to `turns`), never inside the tuple — so a transcript naming no model renders exactly what the original does, and the parity fixture stays model-free to keep pinning the real save path. Anything that reorders or drops turns (`drop_trailing_unanswered`, `delete_exchange`) must move the model with them
- To actually look at the UI: `mh ui --no-browser --port 7777`, then `chromium --headless=new --no-sandbox --hide-scrollbars --window-size=900,9000 --virtual-time-budget=12000 --screenshot=/tmp/shot.png "$URL"` and read the PNG (slice tall pages into bands with pillow). CSS and JS are served from disk per request, so a reload is enough; only `server.py` changes need a restart
- The UI's pure JS (markdown renderer, model labels) is tested for real: `tests/uijs.mjs` slices the functions out of the shipped `index.html` and runs them against a DOM shim; call them from Python with `run_ui_js(...)` in `conftest.py`. These tests skip without `node`, which both CI runners have
